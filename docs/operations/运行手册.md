# How to 运行与验证项目

本文只描述当前代码已经支持的流程。涉及未实现的实时 Provider、自动公开发布或生产后台，请查看对应的改造计划。

## 前置条件

- Python 3.10 或更高版本。
- 本地离线验证只需 Python 标准库和 `pytest`；真实接入、LLM 和 RAG 依赖见 `requirements.txt`。
- 推广卡片渲染需要本机 Chrome 或 Edge；可用 `CHROME_PATH` 指定路径。
- 闲鱼实时私信还需要单独准备 `XianYuApis` 和 Node.js 18+。

## 安装和离线验证

```bash
python -m venv .venv
source .venv/bin/activate              # Windows: .venv\\Scripts\\activate
python -m pip install pytest
# 需要真实平台、LLM 或 RAG 时再安装：
# python -m pip install -r requirements.txt
cp .env.example .env
python -m pytest -q
python -m scripts.run_phase0_check
```

凭证为空时，体检报告中的 `SKIPPED` 是预期结果；`FAILED` 才表示已配置的外部接口异常。

## 运行选品和推广

```bash
# 无 token 时使用离线样例
python -m scripts.run_sourcing_demo 手机支架

# 国内小红书文案和卡片
python -m scripts.run_sourcing_demo 手机支架 --promo

# 跨境 TikTok 英文文案和卡片
python -m scripts.run_sourcing_demo 手机支架 --promo --overseas

# 每日任务或常驻守护
python -m scripts.run_daily_sourcing
python -m scripts.run_scheduler
```

生成的数据库和图片在 `data/`，不会提交到版本库。控制台运行后访问 `http://127.0.0.1:8000`，人工 approve/reject 选品记录；模块处于 `MANUAL` 时，编排层会跳过自动选品。

## 运行闲鱼客服

先在 `.env` 填 `XIANYU_COOKIE` 和 LLM 凭证，再确认 `vendor/XianYuApis` 已准备好。首次验证必须只生成草稿：

```bash
python -m scripts.run_xianyu_live --dry-run
```

`--dry-run` 只接收消息和生成草稿，不向买家发送内容。确认账号、网络和回复质量后，才可以运行默认 LIVE 模式：

```bash
python -m scripts.run_xianyu_live
```

启动前脚本会调用 `get_token` 预检登录态；遇到验证码、风控或过期 Cookie 时，客服模块自动转 `MANUAL` 并退出，不会反复重试。

## 导入商品 RAG

先校验和预览，不连接数据库：

```bash
python -m scripts.ingest_product_snapshots products.jsonl \
  --validate-only --preview data/chunks.preview.jsonl \
  --errors data/import.errors.jsonl
```

配置 `RAG_ENABLED=true` 和 `RAG_DATABASE_URL` 后再导入：

```bash
RAG_ENABLED=true python -m scripts.ingest_product_snapshots products.jsonl --reindex
```

输入必须遵循 [`../product-rag/商品快照JSONL接口规范.md`](../product-rag/商品快照JSONL接口规范.md)。商品 ID 会作为硬过滤条件；未命中、低分、过期或冲突事实必须转为确认/人工处理。

合成测试资料可重新生成：

```bash
python -m scripts.generate_product_test_data
python -m scripts.ingest_product_snapshots data/product_snapshots.test.jsonl --validate-only
```

`TEST-*` 商品和 `test.example.com` 来源只能用于本地测试，不能导入生产知识库。

## 运行商品快照采集器

采集器是独立模块，默认使用离线 fixture：

```bash
cd xianyu_product_crawler
PYTHONPATH=src python -m xianyu_product_crawler \
  --keyword-file keywords.txt \
  --fixture fixtures/provider.json \
  --per-keyword-limit 20 --total-limit 50 --delay 0 \
  --output out/product_snapshots.jsonl \
  --markdown out/review.md --errors out/errors.jsonl
```

人工审核 `out/review.md` 后，再回到项目根目录导入。真实 API 必须是已授权的数据源；登录失效、验证码或安全验证应停止任务，不尝试绕过平台控制。

## 常见问题

| 现象 | 处理 |
|---|---|
| 全部模块为 `SKIPPED` | 复制 `.env.example` 为 `.env`，按模块补齐凭证后重跑体检。 |
| 选品无结果 | 检查 token、关键词和 provider；先用离线样例确认脚本本身正常。 |
| 卡片渲染失败 | 确认 Chrome/Edge 可执行文件，或在 `.env` 设置 `CHROME_PATH`。 |
| 闲鱼预检失败 | 停止重启，按 [`闲鱼安全测试清单.md`](闲鱼安全测试清单.md) 处理 Cookie、账号和风控冷却。 |
| RAG 导入失败 | 先运行 `--validate-only` 查看行号错误；检查时间、URL、金额和 `item_id` 格式。 |

## 清理本机产物

运行产物包括 `data/*.db`、`data/` 下的图片和快照、`xianyu_product_crawler/out/`、`.playwright-cli/`、`.pytest_cache/` 和 `__pycache__/`。它们已加入 `.gitignore`；重新运行测试或脚本会自动生成需要的目录。
