# 客服模块

## 作用与边界

`src/modules/customer/` 负责闲鱼买家消息的意图识别、商品事实问答、阶梯议价、付款后的动作决策，以及售后/发货人工工单。知识检索通过 `product_rag.contracts.ProductKnowledgeRetriever` 注入；客服不负责商品采集、向量库初始化或自动采购。

## 输入、依赖与数据

- 输入：闲鱼消息或 `BuyerMessage`，可带 `item_id`、付款状态和会话信息。
- 依赖：LLM（可选）、商品 RAG（可选）、`vendor/XianYuApis` 和登录态（实时模式）。
- 数据：SQLite 工单由编排层落库；商品事实来自 RAG，不从选品列表临时拼接。

## 使用流程

离线验证：

```bash
python -m scripts.run_customer_sim
```

真实接入先生成草稿，再确认后发送：

```bash
python -m scripts.run_xianyu_live --dry-run
python -m scripts.run_xianyu_live
```

实时接入前配置 `XIANYU_COOKIE`、LLM 凭证和 `vendor/XianYuApis`。详细环境变量见 [`../配置说明.md`](../配置说明.md)，安全纪律见 [`../operations/闲鱼安全测试清单.md`](../operations/闲鱼安全测试清单.md)。

## 行为与状态

- `paid=true` 优先识别为已付款。
- 售后默认转人工；实物付款建立发货工单，虚拟商品只记录自动发货动作。
- 没有可验证商品事实时不编造答案，转为确认或人工处理。
- 模块为 `MANUAL` 时停止自动回复，只创建人工工单。

## 关键入口

- `src/modules/customer/agent.py`：意图路由、回复和议价。
- `src/modules/customer/dispatcher.py`：通道到 Agent 的处理循环。
- `src/modules/customer/xianyu_live.py`：实时桥接。
- `src/modules/customer/knowledge.py`：开发环境词法知识检索。

## 排障

启动预检失败、登录失效、验证码或风控时停止重试，按安全清单冷却并转人工。回答缺少商品事实时检查 `item_id`、RAG 导入状态和快照有效期。
